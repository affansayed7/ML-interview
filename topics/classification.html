Classification: Logistic,
KNN, Naive Bayes, SVM

Four classifiers, four different ways of drawing a boundary between classes. Logistic regression gets the deepest treatment since it's the one interviewers dig into most.

1. Logistic Regression

Say you're predicting whether a loan gets approved: yes or no. Plain linear regression can output any number — 1.5, -0.3, anything — which makes no sense as a probability. Logistic regression fixes this by taking the same weighted sum as linear regression, then squashing it into a 0-to-1 probability using the sigmoid function.

Sigmoid function
$$ \sigma(z) = \frac{1}{1 + e^{-z}} \quad \text{where } z = w^Tx + b $$

The three steps

  1. Compute the weighted sum: $z = w^Tx + b$ — identical to linear regression.
  2. Pass through sigmoid to get a probability: $\hat{y} = \sigma(z)$.
  3. Threshold (usually 0.5): if $\hat{y} \geq 0.5$ predict class 1, else class 0.

Why not use MSE as the cost function?

Plugging sigmoid into squared error produces a bumpy, non-convex cost surface — gradient descent can get stuck in local minima. Instead, logistic regression uses log loss (binary cross-entropy):

Log loss / binary cross-entropy
$$ J(w) = -\frac{1}{n}\sum_{i=1}^{n} \left[ y_i \log(\hat{y}_i) + (1-y_i)\log(1-\hat{y}_i) \right] $$
Reading the formula Only one of the two terms is ever "active" per example, depending on whether the true label is 1 or 0. If the model predicts a probability close to the true label, loss is near zero. If it's confidently wrong — predicting 0.01 when the true label is 1 — the loss shoots toward infinity. This convex, well-behaved shape is exactly why gradient descent reliably converges here.

Interestingly, differentiating this cost function gives a gradient with the exact same clean form as linear regression's: $\frac{\partial J}{\partial w} = \frac{1}{n}X^T(\hat{y} - y)$ — a favorite "derive it on the whiteboard" interview question.

The decision boundary

Assumptions

Linearity between features and the log-odds (not the raw probability), independent observations, minimal multicollinearity between features, and a reasonably large sample size relative to the number of features for stable estimates.

Odds and log-odds (logit)

Odds = $\frac{p}{1-p}$ — probability of the event divided by probability against it. Log-odds is just $\log$ of that. The core insight: logistic regression is really linear regression on the log-odds — that's literally what $z=w^Tx+b$ represents, before sigmoid converts it into a probability.

Multi-class extensions

One-vs-Rest (OvR): train one binary classifier per class (that class vs. everything else), predict the class with the highest probability. Softmax / multinomial regression: generalizes sigmoid directly to $K$ classes, outputting one full probability distribution instead of $K$ separate binary ones.

2. K-Nearest Neighbors (KNN)

KNN makes no assumptions about the data's shape at all — it's a "lazy learner." To classify a new point, look at its $k$ closest neighbors in the training data (by some distance metric, usually Euclidean) and take a majority vote of their labels.

Euclidean distance (most common metric)
$$ d(x, x') = \sqrt{\sum_{i=1}^{n}(x_i - x'_i)^2} $$
Critical detail: feature scaling KNN is entirely distance-based, so features on larger numeric scales (e.g. income in the tens of thousands) will completely dominate the distance calculation over features on smaller scales (e.g. age). Always standardize or normalize features before using KNN — this is one of the most common "what would go wrong" interview traps.

Choosing k: small $k$ (like 1) is very sensitive to noise and overfits; large $k$ smooths the decision boundary but can underfit and blur genuine class boundaries. $k$ is usually chosen via cross-validation, and using an odd number avoids tied votes in binary classification.

3. Naive Bayes

Naive Bayes applies Bayes' theorem to classification, with one simplifying ("naive") assumption: every feature is conditionally independent of every other feature, given the class. This is rarely true in real data, but the model works surprisingly well in practice anyway — especially for text classification like spam filtering.

Bayes' theorem applied to classification
$$ P(y \mid x_1,...,x_n) = \frac{P(y)\prod_{i=1}^{n}P(x_i \mid y)}{P(x_1,...,x_n)} $$

Since the denominator is the same constant across all classes, we can drop it and just pick the class that maximizes the numerator:

$$ \hat{y} = \arg\max_y \; P(y)\prod_{i=1}^{n}P(x_i \mid y) $$

In plain words: for each possible class, multiply the prior probability of that class by how likely each individual feature is, given that class — then pick whichever class gives the highest score.

Why "naive"? Assuming every feature is independent given the class is almost always false — in a spam email, the words "free" and "prize" are correlated, not independent. But Naive Bayes only needs to get the ranking of class probabilities right, not the exact probability values, which is why it still classifies well even when the independence assumption is technically wrong.

Common variants: Gaussian Naive Bayes assumes continuous features are normally distributed within each class; Multinomial Naive Bayes is built for count data (like word frequencies in text); Bernoulli Naive Bayes handles binary/boolean features (like word present-or-not).

The zero-probability problem: if a word in the test set never appeared in training data for a given class, $P(x_i|y) = 0$, which zeroes out the entire product regardless of other evidence. The fix is Laplace (additive) smoothing — adding a small constant to every count so no probability is ever exactly zero.

4. Support Vector Machines (SVM)

SVM takes a different philosophy entirely: instead of modeling probabilities, it looks for the decision boundary (hyperplane) that maximizes the margin — the distance between the boundary and the closest points from each class. Those closest points are called support vectors, and they're the only points that actually determine where the boundary sits.

Hard margin vs. soft margin: a hard margin requires perfect separation with zero misclassifications — unrealistic for most real data. Soft margin SVM introduces a slack variable and a regularization parameter $C$ that trades off margin width against tolerating some misclassified points. Small $C$ → wider margin, more tolerance for errors (less overfitting). Large $C$ → narrower margin, fewer tolerated errors (more overfitting risk).

The kernel trick

Real data is often not linearly separable in its original space. The kernel trick implicitly projects data into a higher-dimensional space where it becomes linearly separable — without ever actually computing the coordinates in that higher-dimensional space, which would be expensive. Common kernels: linear (no transformation), polynomial, and RBF (Radial Basis Function / Gaussian) — RBF is the most popular default since it can model very flexible, non-linear boundaries.

Intuition for the kernel trick Imagine points on a 2D plane where a circle (not a line) separates two classes — impossible for a straight line to solve. Map every point to 3D by adding a third coordinate equal to its distance from the origin, and suddenly a flat plane in 3D can separate them perfectly. The kernel trick computes the effect of this mapping mathematically via a "kernel function," without ever materializing the expensive higher-dimensional coordinates.

Interview Q&A

Why is logistic regression called "regression" if it's used for classification?

Because under the hood it's still fitting a linear equation, $z = w^Tx + b$, exactly like linear regression. The only difference is that $z$ gets passed through sigmoid to convert it into a probability, which is then thresholded into a class. It's linear regression on the log-odds, dressed up for classification.

Likely follow-up "So what exactly does the model learn to be linear in?" — the log-odds of the outcome, not the probability itself. The probability-vs-feature relationship is the S-curve; the log-odds-vs-feature relationship is a straight line.
Why can't you use MSE as the cost function for logistic regression?

Plugging sigmoid into MSE produces a non-convex cost surface with multiple local minima, so gradient descent isn't guaranteed to find the best solution. Log loss (binary cross-entropy) keeps the cost function convex, guaranteeing convergence to the global minimum, and it also penalizes confident wrong predictions much more heavily — which is the behavior you actually want from a probability model.

Likely follow-up "Derive the gradient of the log loss." — it works out to $\frac{1}{n}X^T(\hat{y}-y)$, structurally identical to linear regression's gradient, because the derivative of sigmoid conveniently cancels terms in the chain rule.
How do you handle class imbalance with logistic regression?

Several options: resample the data (oversample the minority class, e.g. SMOTE, or undersample the majority), assign class weights so the model is penalized more for misclassifying the minority class, adjust the classification threshold away from 0.5, or evaluate with precision/recall/F1/ROC-AUC instead of raw accuracy, since accuracy is misleading on imbalanced data.

Likely follow-up "Why is accuracy misleading here?" — if 99% of data is one class, always predicting that class gives 99% accuracy while being completely useless at detecting the minority class.
Why does KNN need feature scaling but logistic regression doesn't strictly need it?

KNN's predictions are based entirely on distance between points, so any feature with a larger numeric range will dominate the distance calculation regardless of its actual importance. Logistic regression instead learns a weight per feature via gradient descent, so it can in principle learn to downweight a large-scale feature — though in practice scaling still helps gradient descent converge faster.

Likely follow-up "Name another distance-based algorithm with the same issue." — K-Means clustering and SVM with an RBF kernel both have the same sensitivity to feature scale.
What happens with very small vs. very large k in KNN?

Very small k (like k=1) fits to individual noisy points, creating a jagged, overfit decision boundary and high variance. Very large k oversmooths the boundary, potentially ignoring genuine local structure and underfitting — in the extreme, k equal to the whole dataset just predicts the majority class everywhere. The right k is usually found via cross-validation, balancing this bias-variance tradeoff.

Likely follow-up "Why use an odd k for binary classification?" — to avoid tied votes that would need arbitrary tie-breaking.
Why is Naive Bayes called "naive," and why does it still work well despite that assumption being false?

It's "naive" because it assumes all features are conditionally independent given the class — in reality, features are almost always correlated to some degree. Despite that, Naive Bayes only needs to correctly rank class probabilities relative to each other, not compute their exact values, so violations of independence often don't change which class ends up with the highest score. This is why it performs surprisingly well on tasks like spam detection even though the independence assumption is clearly wrong.

Likely follow-up "What's Laplace smoothing and why is it needed?" — without it, a feature value unseen in training gives that class a probability of exactly zero regardless of other evidence; adding a small constant to every count avoids this.
What are support vectors, and why does SVM only care about them?

Support vectors are the training points closest to the decision boundary — the ones that actually define where the maximum-margin hyperplane sits. Every other point could be moved (as long as it stays on the correct side, outside the margin) without changing the boundary at all. This is fundamentally different from logistic regression, where every single point contributes to the log loss and therefore influences the final boundary.

Likely follow-up "What does the C parameter control?" — the tradeoff between margin width and tolerating misclassified points; small C allows more slack (wider margin, more bias), large C punishes misclassification harder (narrower margin, more variance).
Explain the kernel trick in SVM in simple terms.

When data isn't linearly separable in its original space, the kernel trick implicitly maps it into a higher-dimensional space where a straight hyperplane can separate it — without ever explicitly computing those higher-dimensional coordinates, which would be computationally expensive or even infinite-dimensional (as with the RBF kernel). Instead, a kernel function computes what the dot product would be in that higher-dimensional space directly from the original points.

Likely follow-up "When would you pick a linear kernel over RBF?" — when the data is already close to linearly separable and you want a simpler, faster, less overfit-prone model, or when the number of features is very large relative to the number of samples (common in text data).
Compare logistic regression, KNN, Naive Bayes, and SVM at a high level — when would you pick each?

Logistic regression: fast, interpretable, gives calibrated probabilities — good default baseline, works best when classes are roughly linearly separable. KNN: simple, no training phase, but slow at prediction time on large datasets and sensitive to feature scale and irrelevant features. Naive Bayes: extremely fast to train, works well on high-dimensional sparse data like text, but the independence assumption limits accuracy on strongly correlated features. SVM: strong performance on complex, non-linear boundaries via kernels, robust to outliers far from the margin, but slower to train on very large datasets and less naturally interpretable.

Likely follow-up "Which would you pick for a spam classifier and why?" — Naive Bayes is a classic strong baseline for text/spam because it handles high-dimensional sparse word-count features efficiently and trains almost instantly, even though its independence assumption is technically violated by correlated words.
