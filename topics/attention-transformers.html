§15 · Deep Learning

Attention &
Transformers

The single most-asked architecture right now. Everything downstream — BERT, GPT, your LangChain/Mistral project — is built on the mechanism explained here. We go word-by-word first, then the matrix math.

1. The black box, then opened up

At the highest level, a Transformer takes an input sequence and produces an output sequence — translation, summarization, next-token prediction, all fit this shape. Opening the box: it's a stack of identical encoder blocks feeding a stack of identical decoder blocks (the original paper used 6 of each).

Each encoder block has exactly two sub-layers: self-attention, then a feed-forward network. Each decoder block has three: masked self-attention, encoder-decoder attention, then feed-forward. Every sub-layer is wrapped in a residual connection + layer normalization ("Add & Norm") — more on why that matters in §4.

2. Self-attention — the word-by-word intuition

This is the core idea, and it's easiest to build up with one sentence: "The animal didn't cross the street because it was too tired." What does "it" refer to — the animal, or the street? Self-attention is the mechanism that lets the model figure this out: when processing the word "it", the model looks at every other word in the sentence and learns to weight "animal" heavily and "street" barely at all.

To make this learnable, every word's embedding is projected into three separate vectors:

  • Query (Q) — "what am I looking for?" — a representation of the current word used to search other words
  • Key (K) — "what do I contain?" — a representation of each word used to be matched against a query
  • Value (V) — "what do I actually offer?" — the content that gets pulled forward once a match is found

These come from three learned weight matrices ($W^Q, W^K, W^V$) applied to the same input embedding — so Q, K, and V for a word all start from the same place but are projected differently for different purposes.

Scaled dot-product attention (the full matrix form)
$$ \text{Attention}(Q,K,V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V $$

Why divide by √dₖ?

As the dimension $d_k$ of the key vectors grows, dot products $Q \cdot K$ tend to grow large in magnitude purely from summing more terms. Large values pushed into softmax produce an extremely peaked, near one-hot distribution — gradients through softmax in that regime become tiny, stalling learning. Scaling by $\sqrt{d_k}$ keeps the dot products in a reasonable range so softmax stays well-behaved and gradients flow properly.

3. Multi-head attention

One attention computation lets the model focus on one kind of relationship at a time. But language has many simultaneous relationships — "it" resolving to "animal" is a coreference relationship; "tired" relating back to "animal" is a different, semantic one. Multi-head attention runs several attention computations in parallel, each with its own learned $W^Q, W^K, W^V$, so different heads can specialize in different relationship types — then concatenates all the results and projects back down.

Multi-head attention
$$ \text{MultiHead}(Q,K,V) = \text{Concat}(\text{head}_1, ..., \text{head}_h)\,W^O $$ $$ \text{head}_i = \text{Attention}(QW_i^Q,\ KW_i^K,\ VW_i^V) $$

4. Positional encoding — injecting word order

Self-attention has no inherent sense of sequence order — it treats the input as a set, computing the same attention regardless of word position. But order obviously matters ("dog bites man" ≠ "man bites dog"). The fix: add a positional encoding vector to each word's embedding before it enters the encoder, using fixed sine and cosine functions at different frequencies.

Sinusoidal positional encoding
$$ PE_{(pos, 2i)} = \sin\left(\frac{pos}{10000^{2i/d_{model}}}\right) $$ $$ PE_{(pos, 2i+1)} = \cos\left(\frac{pos}{10000^{2i/d_{model}}}\right) $$

Different dimensions of the encoding oscillate at different frequencies — low dimensions change quickly with position, high dimensions change slowly — giving every position a unique "fingerprint" while keeping the encoding bounded and allowing the model to generalize to sequence lengths not seen during training (since sine/cosine functions are well-defined at any position).

5. Residual connections & layer normalization

Every sub-layer's output is combined as $\text{LayerNorm}(x + \text{Sublayer}(x))$ — the input skips around the sub-layer and is added back before normalizing. The residual connection gives gradients a direct path backward through the entire stack (the same motivation as ResNet in CNNs), which is essential for training networks this deep. Layer normalization (normalizing across the feature dimension, per example) stabilizes training — Transformers use LayerNorm rather than BatchNorm because it doesn't depend on batch statistics, which matters for variable-length sequences and small batch sizes.

6. The decoder's extra piece: masked self-attention

The decoder can't be allowed to "cheat" by looking at future tokens it hasn't generated yet. So its self-attention layer applies a mask — setting attention scores for all future positions to $-\infty$ before the softmax, so they become exactly 0 after softmax. This forces each position to only attend to itself and earlier positions, matching how generation actually happens one token at a time at inference.

7. Final output

After the last decoder block, a final linear layer projects the output into a vector the size of the vocabulary, and softmax converts that into a probability distribution over every possible next token — the model then picks (or samples) the highest-probability token as its output.

Interview Q&A

Walk through self-attention step by step, using the Query/Key/Value framing.

Every word's embedding is projected into a Query, Key, and Value vector using three learned weight matrices. To compute the output for a given word, take the dot product of its Query with every word's Key (including its own) — this gives a raw similarity score per word. Scale these scores by $\sqrt{d_k}$, pass them through softmax to get attention weights that sum to 1, then take the weighted sum of every word's Value vector using those weights. The result is a new representation of the word that's been enriched with relevant context from the rest of the sequence.

Likely follow-up "Why do we need three separate projections (Q, K, V) instead of just using the raw embeddings directly?" — separate learned projections let the model decouple "what I'm looking for" from "what I contain" from "what I actually pass along" — using the same vector for all three would tightly couple these roles and limit what the model can learn to represent.
Why scale the dot product by √dₖ before softmax?

As the key dimension $d_k$ grows, dot products between Q and K vectors tend to have larger magnitude purely because you're summing more terms. Large inputs to softmax produce an extremely peaked, near-one-hot output distribution, and the gradient of softmax in that saturated regime is very small — this stalls learning. Dividing by $\sqrt{d_k}$ counteracts this growth and keeps the softmax input in a range where gradients remain useful.

Likely follow-up "Why specifically √dₖ and not dₖ itself?" — assuming Q and K components are roughly independent with unit variance, the variance of their dot product scales with $d_k$, so dividing by its square root normalizes the variance back to approximately 1.
Why use multiple attention heads instead of one large attention computation?

A single attention head computes one weighted average over the sequence, which forces it to average across potentially very different types of relationships (syntactic, coreference, semantic) into one representation. Multiple heads, each with independently learned Q/K/V projections, let the model attend to different relationship types in parallel — one head might specialize in tracking pronoun references, another in local syntax — and concatenating them preserves this diversity instead of collapsing it into a single average.

Likely follow-up "Does adding more heads always help?" — no, there are diminishing (and eventually negative) returns; too many heads with too little dimension each can undermine any single head's ability to represent a relationship well, and it's an empirical hyperparameter tuned per model.
Why do Transformers need positional encoding at all?

Self-attention computes a weighted sum over the whole sequence with no built-in notion of order — mathematically, shuffling the input words would produce the same set of attention outputs just reordered, meaning the model can't natively distinguish "dog bites man" from "man bites dog". Positional encoding solves this by adding a unique, order-dependent vector to each token's embedding before the first layer, giving the model information about relative and absolute position that it can then use however it learns is useful.

Likely follow-up "Why sine and cosine functions specifically, instead of just using the raw position number?" — sinusoids are bounded (won't blow up for long sequences the way a raw large position number would), and their specific mathematical structure allows the model to easily learn to attend by relative position, since $PE_{pos+k}$ can be expressed as a linear function of $PE_{pos}$.
What's the purpose of masking in the decoder's self-attention?

At inference, the decoder generates tokens one at a time and genuinely cannot see future tokens — they don't exist yet. To train consistently with how the model will actually be used, masked self-attention sets the attention scores for all future positions to $-\infty$ before softmax (making their weight exactly 0 after softmax), forcing each position to only attend to itself and earlier positions. Without this mask, the model would learn to "cheat" during training by peeking at the answer, and would fail catastrophically at real generation time.

Likely follow-up "Is this the same reason BERT doesn't use this mask?" — right, BERT is trained on masked language modeling (predicting randomly masked tokens using full bidirectional context), not autoregressive generation, so it deliberately uses unmasked, bidirectional self-attention across the whole input instead.
What is encoder-decoder attention, and how does it differ from self-attention?

In self-attention, Q, K, and V all come from the same sequence (the encoder attending to itself, or the decoder attending to itself). In encoder-decoder attention, the Queries come from the decoder's current state, while the Keys and Values come from the encoder's final output — this lets each decoder position "look back" at the entire input sequence to decide what's relevant for generating the next output token, which is the mechanism that actually performs the translation/mapping between input and output sequences.

Likely follow-up "Is encoder-decoder attention masked like the decoder's self-attention?" — no, it's unmasked; the decoder is allowed to see the entire input sequence (that's the whole point), the mask only applies to the decoder's own previously-generated output tokens.
Why do Transformers use LayerNorm instead of BatchNorm?

BatchNorm normalizes across the batch dimension for each feature, which requires meaningful batch statistics and behaves inconsistently with variable-length sequences and small batch sizes (both common in NLP). LayerNorm instead normalizes across the feature dimension independently for each individual example, making it insensitive to batch size or sequence length — a better fit for sequence models where inputs naturally vary in length.

Likely follow-up "Where exactly are the residual connections and LayerNorm applied in each sub-layer?" — as $\text{LayerNorm}(x + \text{Sublayer}(x))$: the sub-layer's output is added back to its own input (the residual/skip connection) before the sum is normalized.
What's the computational complexity of self-attention with respect to sequence length, and why does it matter?

Self-attention computes a score between every pair of positions in the sequence, giving $O(n^2)$ time and memory complexity with respect to sequence length $n$ — compared to an RNN's $O(n)$ per-step (though sequential) processing. This quadratic cost is the reason very long context windows are expensive, and it's the direct motivation behind efficient-attention research (sparse attention, linear attention, sliding-window attention) used in modern long-context LLMs.

Likely follow-up "Given this tradeoff, when might an RNN actually still be preferable to a Transformer?" — for very long sequences under tight memory/latency constraints (e.g. real-time streaming), where RNNs' constant per-step memory can beat attention's quadratic blow-up, even though RNNs sacrifice parallelizability and long-range gradient flow.
What's the structural difference between an encoder-only, decoder-only, and encoder-decoder Transformer, and give an example model of each.

Encoder-only (e.g. BERT) uses unmasked, bidirectional self-attention — good for understanding tasks (classification, NER) where you have the full input upfront. Decoder-only (e.g. GPT) uses masked, causal self-attention only — built for autoregressive generation, predicting one token at a time from left to right. Encoder-decoder (e.g. the original Transformer, T5) uses both: an encoder to understand the input plus a decoder with cross-attention into it — a natural fit for sequence-to-sequence tasks like translation or summarization.

Likely follow-up "Which category does a model like Mistral 7B fall into, and why does that matter for how you'd use it?" — decoder-only, like GPT; that's why it's used for open-ended text generation and chat rather than the fill-in-the-blank style tasks BERT excels at — this is exactly the distinction to know going into §20's Applied LLMs section.
