§14 · Deep Learning

RNNs, LSTM
& GRU

The architectures that made sequence modeling work before Transformers took over — still asked constantly, because they're where "vanishing gradients" and "gates" actually make intuitive sense for the first time.

1. Why plain RNNs exist

Feedforward networks assume every input is independent — but language, time series, and audio all have order: what comes next depends on what came before. A Recurrent Neural Network handles this by carrying a hidden state forward through time, updating it at every step with both the new input and everything it remembers so far.

RNN recurrence
$$ h_t = \tanh(W_{hh}\,h_{t-1} + W_{xh}\,x_t + b_h) $$ $$ y_t = W_{hy}\,h_t + b_y $$

The same weight matrices $W_{hh}, W_{xh}, W_{hy}$ are reused at every timestep — this weight sharing is what lets an RNN handle sequences of any length with a fixed number of parameters.

2. Backpropagation Through Time & the vanishing gradient problem

Training an RNN means backpropagating the loss all the way back through every timestep — called BPTT. The gradient with respect to an early hidden state involves a product of many Jacobians, one per timestep in between:

Gradient flowing back through time
$$ \frac{\partial h_t}{\partial h_0} = \prod_{k=1}^{t} \frac{\partial h_k}{\partial h_{k-1}} \approx \prod_{k=1}^{t} W_{hh}^T \cdot \text{diag}(\tanh'(\cdot)) $$

If the repeated term is consistently less than 1, this product shrinks exponentially toward zero as $t$ grows — the vanishing gradient problem, where early timesteps get virtually no learning signal and the model "forgets" long-range dependencies. If it's consistently greater than 1, gradients explode instead, causing unstable, huge weight updates. Because $\tanh'(\cdot) \le 1$ always, and is often much smaller, vanishing is the far more common failure mode in practice.

Why this matters A plain RNN can technically "see" 50 timesteps back, but if the gradient from timestep 50 has vanished to near-zero by the time it reaches timestep 1, the model never actually learns to use information that far back. LSTM and GRU exist specifically to fix this.

3. LSTM — Long Short-Term Memory

LSTM's key idea: maintain a separate cell state $C_t$ that acts like a conveyor belt running through the whole sequence, modified only by simple, mostly-linear operations (not squashed through tanh every step). Three "gates" — each a sigmoid layer producing values between 0 and 1 — control what gets added to, removed from, or read out of that cell state.

Forget gate — what to erase from the cell state
$$ f_t = \sigma(W_f \cdot [h_{t-1}, x_t] + b_f) $$
Input gate — what new info to write in
$$ i_t = \sigma(W_i \cdot [h_{t-1}, x_t] + b_i) $$ $$ \tilde{C}_t = \tanh(W_C \cdot [h_{t-1}, x_t] + b_C) $$
Cell state update
$$ C_t = f_t \odot C_{t-1} + i_t \odot \tilde{C}_t $$
Output gate — what to expose as the hidden state
$$ o_t = \sigma(W_o \cdot [h_{t-1}, x_t] + b_o) $$ $$ h_t = o_t \odot \tanh(C_t) $$

Why this actually fixes vanishing gradients

The cell state update $C_t = f_t \odot C_{t-1} + i_t \odot \tilde{C}_t$ is additive, not repeatedly squashed through a nonlinearity like the plain RNN's hidden state. When the forget gate is close to 1, gradient can flow backward through the cell state almost unchanged across many timesteps — this pathway is often called the constant error carousel. The gates are learned, so the network can decide for itself when to preserve long-range information and when to discard it.

4. GRU — Gated Recurrent Unit

GRU is a simplification: it merges the cell state and hidden state into one, and uses only two gates instead of three — fewer parameters, faster to train, and in practice performs comparably to LSTM on most tasks.

Update gate — how much of the past to keep
$$ z_t = \sigma(W_z \cdot [h_{t-1}, x_t]) $$
Reset gate — how much past to ignore when proposing new content
$$ r_t = \sigma(W_r \cdot [h_{t-1}, x_t]) $$
Candidate activation
$$ \tilde{h}_t = \tanh(W \cdot [r_t \odot h_{t-1}, x_t]) $$
Final hidden state — a blend of old and new
$$ h_t = (1 - z_t) \odot h_{t-1} + z_t \odot \tilde{h}_t $$
LSTM vs GRU — how to answer the tradeoff question GRU has 2 gates and one state vector; LSTM has 3 gates and two state vectors (cell + hidden). GRU trains faster and needs less data due to fewer parameters. LSTM's separate cell state gives it slightly more expressive control over memory, which can matter on very long sequences or larger datasets. In practice: try GRU first for speed, reach for LSTM if you have ample data and need that extra memory capacity — but always benchmark both, since no architecture reliably wins across all tasks.

5. Where these still get used

Transformers have replaced RNN/LSTM/GRU for most large-scale NLP, but recurrent architectures are still relevant for: time-series forecasting, smaller datasets where a Transformer's data hunger is a liability, streaming/low-latency inference (RNNs process one token at a time with constant memory, unlike attention's quadratic cost), and as a component inside larger systems (e.g. decoders in some speech models).

6. Quick implementation

PyTorch
import torch.nn as nn

lstm = nn.LSTM(input_size=128, hidden_size=256, num_layers=1, batch_first=True)
output, (h_n, c_n) = lstm(x)   # x: (batch, seq_len, input_size)

gru = nn.GRU(input_size=128, hidden_size=256, num_layers=1, batch_first=True)
output, h_n = gru(x)           # GRU has no separate cell state

Interview Q&A

Explain why plain RNNs suffer from vanishing gradients, in your own words.

Backpropagation through time requires multiplying the same recurrent weight matrix (and the derivative of tanh, which is always ≤1) once per timestep going backward. Multiplying many numbers less than 1 together shrinks the product exponentially toward zero, so gradients from early timesteps become vanishingly small by the time they influence weight updates — the model effectively can't learn dependencies spanning many steps.

Likely follow-up "What's the difference between vanishing and exploding gradients, and when does each happen?" — vanishing happens when the repeated multiplicative term is consistently <1 (shrinks to 0); exploding happens when it's consistently >1 (grows unboundedly). Exploding gradients are usually fixed with gradient clipping; vanishing gradients need an architectural fix like LSTM/GRU.
Why does the LSTM cell state help with the vanishing gradient problem specifically?

Because the cell state is updated additively ($C_t = f_t \odot C_{t-1} + i_t \odot \tilde{C}_t$) rather than being passed through a squashing nonlinearity and matrix multiplication at every step like a plain RNN's hidden state. When the forget gate stays near 1, gradients can flow backward through the cell state pathway almost unchanged across long spans — this near-linear path is sometimes called the constant error carousel.

Likely follow-up "Does LSTM completely eliminate vanishing gradients?" — No, it mitigates it substantially but not perfectly; extremely long sequences can still be challenging, which is part of why attention/Transformers ultimately displaced RNNs for very long-range dependencies.
Walk through what each of the three LSTM gates does.

The forget gate looks at the previous hidden state and current input and outputs a value between 0 and 1 per cell-state dimension, deciding how much of the old cell state to keep versus erase. The input gate decides how much of a newly computed candidate value to write into the cell state. The output gate decides how much of the (now updated) cell state to expose as the hidden state that gets passed forward and used for predictions.

Likely follow-up "Why sigmoid for the gates but tanh for the candidate values?" — sigmoid outputs values in [0,1], which naturally represents "how much to let through" (a gate); tanh outputs [-1,1], centered at zero, which is better suited for representing actual content/state values that can be positive or negative.
What's the practical difference between LSTM and GRU, and which would you pick?

GRU merges the cell and hidden states into one and uses 2 gates (reset, update) instead of LSTM's 3 (forget, input, output) and separate cell state — fewer parameters, faster training, less data required to train well. LSTM's extra cell state and gate give it more fine-grained control over memory, which can matter for longer sequences or larger datasets. In practice the performance gap is often small and task-dependent, so a reasonable answer is: start with GRU for speed/simplicity, and benchmark LSTM if you have the data and compute to justify it.

Likely follow-up "How many total gates does an LSTM have, and how many weight matrices does that imply?" — 3 gates plus 1 candidate-value computation = 4 sets of weights, each taking the concatenated $[h_{t-1}, x_t]$ as input — this is part of why LSTM has roughly 4x the parameters of a plain RNN cell of the same hidden size.
What is a bidirectional RNN/LSTM, and when would you use one?

A bidirectional RNN runs two separate recurrent layers over the sequence — one left-to-right, one right-to-left — and concatenates (or otherwise combines) their hidden states at each position. This lets every timestep's representation incorporate context from both the past and the future. It's useful whenever the full sequence is available upfront (e.g. text classification, NER) but is not usable for real-time/streaming generation tasks, since it requires seeing the entire sequence before producing any output.

Likely follow-up "Why can't you use a bidirectional model for something like next-word prediction during generation?" — because generation is autoregressive: you don't have future tokens yet when predicting the next one, so there's no "future" context available to run the backward pass over.
How do you handle exploding gradients in practice?

The standard fix is gradient clipping — if the norm of the gradient exceeds some threshold, rescale it down to that threshold before applying the update. This caps how large a single weight update can be without changing the gradient's direction, preventing the wild instability that comes from occasional huge gradients while leaving normal training mostly unaffected.

Likely follow-up "Does gradient clipping help with vanishing gradients too?" — No, clipping only caps large gradients; it does nothing for gradients that are already near zero. Vanishing requires an architectural fix (LSTM/GRU, residual connections, better initialization), not clipping.
Why did Transformers largely replace RNNs/LSTMs for NLP?

Two main reasons. First, RNNs process tokens strictly sequentially — you can't compute timestep 5 before timestep 4 — which makes training slow and prevents parallelization across the sequence dimension; Transformers process all tokens in parallel via attention. Second, even LSTM's improved gradient flow degrades over very long sequences, while self-attention gives every token a direct, single-hop connection to every other token regardless of distance, making long-range dependencies far easier to learn.

Likely follow-up "Are RNNs completely obsolete then?" — Not entirely: they remain relevant for streaming/low-latency settings (constant memory per step vs attention's quadratic cost), smaller datasets, and time-series tasks where the strict sequential inductive bias can actually help rather than hurt.
What does "long-term dependency" mean in the context of RNNs, and give an example where it matters.

It refers to a case where correctly predicting something at position $t$ requires information from far earlier in the sequence, past many intervening timesteps. Classic example: "The clouds in the sky, having drifted in from the coast overnight after a long and unusual storm, are ___" — predicting the missing word (e.g. "grey") requires connecting back to "clouds" many words earlier, well beyond where a plain RNN's gradient signal typically survives.

Likely follow-up "How would you empirically test whether your model is actually using long-range context or just recent tokens?" — ablation: shuffle or mask distant tokens and see if performance degrades; if it doesn't change much, the model likely isn't using that long-range signal regardless of architecture.
